# ADR 008: Fresh jti per Attempt, Stable Idempotency-Key per Create

**Status:** Accepted
**Date:** 2026-10-21
**Deciders:** Konsulin central

## Context

Party requests carry a single-use `jti`; the gateway dedupes it (replay
protection). Creates carry an `Idempotency-Key`; the gateway dedupes the
*logical operation* across retries. The SDK retries transient failures
(SDK-RETRY-002: network errors, `409 idempotency_in_progress`, `429`, `502`,
`503`, `504`). Two dedupe scopes with opposite retry semantics means the
wrong choice on either axis breaks one guarantee: reusing a `jti` on retry
trips replay protection and fails the retried request; changing the
`Idempotency-Key` across retries turns one logical create into several.

## Decision

- **Fresh `jti` (and fresh `iat`) per attempt** (SDK-AUTH-003,
  SDK-RETRY-001): every signed attempt — including a retry of the same
  logical request — mints a new `jti`. A retried request never carries a
  previous attempt's `jti`.
- **`Idempotency-Key` stable per logical create** (SDK-CLIENT-002,
  SDK-RETRY-001): generated by the SDK when the caller does not supply one,
  constant across all retries of that one create, never reused across
  different operations.
- `SDK-RETRY-C01` pins the semantics: a 409→200 sequence replays with the
  **same** `Idempotency-Key` and a **different** `jti`; a 403 is terminal on
  the first response.
- Retries re-sign through the same path as first attempts — there is no
  "cached signed request" shortcut anywhere in `client`/`auth`.

## Consequences

**Positive:**
- The gateway's two dedupe layers both work as intended: `jti` dedupe never
  false-positives on an honest retry, idempotency dedupe collapses retried
  creates into one operation.
- One rule covers every attempt; no per-route special casing.

**Negative:**
- Two identifiers with different lifetimes must be reasoned about by
  maintainers (a classic source of retry bugs) — pinned by SDK-RETRY-C01 and
  covered by the offline e2e flows.
- Slight extra signing cost per retry (a signature op per attempt) —
  negligible against the <1 ms p95 budget.
