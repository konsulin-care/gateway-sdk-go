# Phase 5 — v0.1.1 Backend Adoption (SDKP-*)

## Objective

Land every `SDKP-*` requirement from [ADDENDUM.md](../../ADDENDUM.md) so
the backend's adapter package (`internal/app/drivers/gateway`) can
migrate: Bound Envelope helpers, enc-key resolution, delivery claims,
payment return-URL fields, typed settlement/delivery payloads, key
parsing, listing filters, docs/interface cleanup, and the conformance
party-health URL. Exit: everything ships as **SDK `v0.1.1`, paired with
gateway `v0.1.2`** (ADDENDUM §4).

## Ground rules

Each checklist item is one `SDKP-*` behavior: the behavior, its
accept/deny expectation, and the test that proves it — TDD, failing test
first (AGENTS.md). Every offline test runs with zero network and reads
only in-module paths; the gateway checkout is an authoring-time
reference, never a test dependency (ADR-004). A checked box means the
named proving test is present in-tree; unchecked means work is
outstanding. Re-run `go test -race ./...` and `mise run qc` after each
item.

## Checklist

### `SDKP-001` (M) — Bound Envelope helpers

- [x] **Behavior**: `envelope.SealBound` seals the wrapper
  `{v, from, to, service, iat, nonce, data}` inside the compact JWE;
  `envelope.OpenBound` checks `v` (unknown rejected), `from`, `to`,
  `service`, `iat` against the freshness window (**default 5 min,
  recipient-configurable up to a 15 min cap**; >60 s in the future always
  rejected) and dedupes the nonce per the gateway rule — ≥128-bit random
  base64url sender value, non-empty ≤ 64 chars accepted, repeated
  `(from, nonce)` rejected, retained ≥ window + 60 s (**10 min** at the
  default window) via `wire.ReplayCache`; expectations derive from the
  verified delivery claims; ships an **SDK-owned decrypt fixture** (not
  mirrored).
- **Accept**: round-trip opens offline; stale-`iat` and replayed-nonce
  negatives fail closed; the fixture is verified by the n8n reference
  sub-workflow.
- **Deny**: mismatched binding, out-of-window `iat`, a repeated
  `(from, nonce)` inside retention, or a nonce-cache error denies with
  nil data — never a partial accept; the fixture never lives under
  `testdata/golden/` (SDK-owned, not mirrored).
- **Proving tests**: `TestSealBoundOpenBoundRoundTrip`,
  `TestOpenBoundIatFreshness` (4m59s ok / 5m01s rejected / +61 s
  rejected), `TestEffectiveMaxAge` (5 min default, 15 min cap),
  `TestOpenBoundRejectsNonceReplay`, `TestOpenBoundNonceReplayReservationWindow`,
  `TestBoundDecryptVector` (`envelope/`).

### `SDKP-002` (M) — Recipient enc-key resolution

- [x] **Behavior**: a selection helper returns the recipient's single
  active `use:enc` key from the party JWKS alone; a cached resolver
  (per-party, TTL) refetches once on seal/open failure — rotation-safe,
  never a tight loop.
- **Accept**: offline tests cover cache hit, TTL expiry, unknown-key
  refetch and a missing `use:enc` key.
- **Deny**: zero or multiple `use:enc` keys, or a resolver failure,
  fails closed — no guessed key, no unbounded refetch.
- **Proving tests**: `TestSelectRecipientEncKeySingleEncKey`,
  `TestSelectRecipientEncKeyNone`, `TestSelectRecipientEncKeyAmbiguous`,
  `TestEncKeyResolverResolveCachesWithinTTL`,
  `TestEncKeyResolverRefreshForcesOneFetchRateLimited`,
  `TestSealRecipientEncKeyDiscovery` (`envelope/`).

### `SDKP-003` (M) — Verify claims expose `service` and `listing_id`

- [x] **Behavior**: the verify claims struct carries `service` and
  `listing_id` from every `ks-delivery+jwt`; the middleware exposes them
  on the request context; the `ks-delivery.json` mirror carries both.
- **Accept**: the golden vector with both claims verifies; claims are
  readable from the request context after the middleware.
- **Deny**: a delivery *without* `service` still verifies (fields are
  additive); a Bound-Envelope wrapper `service` that contradicts the
  signed claim is denied by `OpenBound`, not by the middleware.
- **Proving tests**: `TestGoldenDeliveryServiceAndListingID`,
  `TestMiddlewareExposesServiceAndListingID`,
  `TestDeliveryWithoutServiceStillVerifies` (`verify/`).

### `SDKP-004` (M) — Payment return URL fields

- [x] **Behavior**: `wire.CreatePaymentRequest` gains
  `success_return_url` and `cancel_return_url` (`omitempty`), matching
  GWP-001; validation stays the gateway's.
- **Accept**: DTO round-trip; the serialized body matches the Bruno
  origin-mismatch negative example field-for-field.
- **Deny**: no other field or behavior change; the removed legacy
  whole-word `return_url` field never reappears (gateway release-readiness
  grep).
- **Proving tests**: `TestCreatePaymentRequestReturnURLsMarshal`,
  `TestCreatePaymentRequestReturnURLsOmitted` (`wire/`).

### `SDKP-005` (S) — Typed settlement and delivery payloads

- [x] **Behavior**: typed `wire.SettlementNotification` (`payment_id`,
  `external_id`, `status` `PAID`/`EXPIRED`/`CANCELED`,
  `payment_session_id`, `amount`, `currency`, `occurred_at`,
  `access_token_url`); `wire.ParseExternalID` → `(party, domain, opaque)`
  (three parts, no `:` in any part); typed delivery body
  `{envelope, result_ticket}` plus the sync-reply content type
  `application/jose`; the async result body `{result}` **reuses the
  existing `wire.WebhookResultRequest`** — no new type.
- **Accept**: round-trip tests per type; malformed `external_id`
  rejected; shapes match the Bruno settlement and delivery examples.
- **Deny**: an `external_id` that does not match the rule errors — never
  a silent split; no duplicate result-body struct is introduced while
  `wire.WebhookResultRequest` exists.
- **Proving tests**: `TestSettlementPaidRoundTrip`,
  `TestSettlementFreePathNullSession`,
  `TestSettlementUnknownStatusAndConstants`, `TestParseExternalIDValid`,
  `TestParseExternalIDInvalid`, `TestDeliveryBodyRoundTrip` (`wire/`).

### `SDKP-006` (S) — Key parsing helpers

- [x] **Behavior**: parse `cmd/genkey` output — Ed25519 std base64
  (32-byte seed or 64-byte key), X25519 std base64 32 bytes — derive the
  public key, RFC 7638 `kid` and the `use:enc` JWK; key material never
  logged nor included in error strings.
- **Accept**: golden tests: genkey-format input → public key, kid and
  JWK match fixed expectations; malformed and truncated inputs fail
  closed.
- **Deny**: an error string containing input key material, or a
  malformed/truncated key that parses, fails the test.
- **Proving tests**: `TestParseEd25519PrivateKeyGoldenKid`,
  `TestParseEd25519PrivateKeySeedForm`,
  `TestParseEd25519PrivateKeyErrorsOmitInput` (`auth/`);
  `TestParseX25519PrivateKeyGoldenVector`, `TestEncJWKThumbprintAndSelect`,
  `TestParseX25519PrivateKeyErrorsOmitInput` (`envelope/`).

### `SDKP-007` (S) — Listings lookup

- [x] **Behavior**: `listings.List` gains filters (`name`,
  `provider_party_id`, `invocation`) matching GWP-005, carried on the
  `client.Request.Query` (`url.Values`) field, plus
  `FindByName(providerPartyID, name)` that errors on ambiguity (0 or >1
  active matches).
- **Accept**: offline tests: filter round-trip on the wire, single
  match, ambiguous and missing-name errors.
- **Deny**: 0 or >1 active matches → error, never a guessed row; the
  query rides unsigned (`ks-party` covers `body_sha256` only) and stays
  byte-identical across retries.
- **Proving tests**: `TestListSendsFilterQueryParams`,
  `TestFindByNameReturnsSingleMatch`,
  `TestFindByNameErrorsWhenNotExactlyOneMatch` (`listings/`);
  `TestDoSendsQueryParametersOnRequestPath`, `TestEveryRetryAttemptDeliversSameRawQuery`
  (`client/`).

### `SDKP-008` (C) — Interface and docs cleanup

- [ ] **Behavior**: one shared `wire.ReplayCache` interface used by both
  `client` and `verify` (type aliases, one consumer adapter type); the
  README states the released version (drop "Pre-v0.1.0"); the PRD Go
  version item is **already true** (PRD says Go 1.27, `go.mod` is
  `go 1.27` — no change needed); every contract-affecting item updates
  `COMPATIBILITY.md` and `CHANGELOG.md` in the same PR.
- **Accept**: the single interface compiles both call sites; docs state
  the released version and Go 1.27.
- **Deny**: two parallel `ReplayCache` interfaces must not survive, and
  the README must not claim an unreleased state.
- **Proving test**: `TestReplayCacheSharedAcrossPackages`
  (`wire/replay_test.go`) for the interface; the README / matrix items
  are release-PR inspections, not unit tests. **Outstanding**: README
  still says "Pre-v0.1.0"; the `v0.1.1` `COMPATIBILITY.md` row and
  `CHANGELOG.md` entry land in the release PR.

### `SDKP-009` (M) — Conformance runner: configurable party health URL

- [x] **Behavior**: `configFrom` reads a `-party-health-url` flag and a
  `CONFORMANCE_PARTY_HEALTH_URL` env var into `Config.PartyHealthURL`;
  the flag overrides the env var; unset keeps the current default
  (additive, non-breaking).
- **Accept**: `cmd/conformance/main_test.go` covers flag, env,
  flag-over-env precedence and the unset default;
  `cmd/conformance/README.md`, `CHANGELOG.md` and `COMPATIBILITY.md`
  updated; the gateway's local `sh scripts/conformance.sh` passes all 20
  cases. Ships as `v0.1.1` (§4).
- **Deny**: unset must not change the hard-coded default
  (`http://127.0.0.1:8080/health`), and the env var must never override
  an explicit flag.
- **Proving test**: `TestConfigReadsPartyHealthURLFromEnvAndFlagOverrides`
  (`cmd/conformance/main_test.go`).

## Flagged upstream

Gateway-owned items discovered while writing this phase. None blocks the
SDK work or its offline tests; each is tracked here so the mirror and
release PRs account for it.

- **Settlement golden placeholders** — the mirrored
  `testdata/golden/settlement-*.json` bodies are placeholder payloads
  (`{"payment_id":"pay-golden-…","status":"paid"}`), not the full
  settlement-notification shape (uppercase `PAID`, `external_id`,
  `occurred_at`, …). ADR-004 forbids local edits: regenerate upstream
  with representative bodies, then re-mirror. SDKP-005 tests use their
  own typed fixtures, so this is mirror debt, not a test blocker.
- **Token Kinds row lacks `service`/`listing_id` (G8)** — the gateway's
  `docs/api/AGENTS.md` Token Kinds row for `ks-delivery+jwt` does not
  list the two claims GWP-002 added; the fixture already carries them and
  SDK verify exposes them (SDKP-003). Doc-only upstream fix, flag **G8**;
  non-blocking.
- **G6/G7 non-blocking** — upstream flags G6 and G7 from the gateway's
  G1–G7 change set are tracked gateway-side and are non-blocking for SDK
  `v0.1.1`; the SDK release gate is its own green `mise run qc` plus
  green conformance.
- **Pre-tag mirror re-run against gateway `v0.1.2`** —
